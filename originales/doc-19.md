# Plan de Carrera y Desarrollo de Competencias — VeteriSoft

**Propósito:** convertir la matriz de competencias de VeteriSoft en una ruta de desarrollo profesional vinculada con los entregables del proyecto. Esta propuesta dura nueve meses y debe ajustarse cuando se confirmen las funciones y se evalúen las competencias con evidencia.

## 1. Alcance y criterios

El plan toma como base la Matriz de Competencias y Plan de Mejora — VeteriSoft, que define competencias para dirección, análisis, arquitectura/backend, frontend, datos, QA y DevOps.

- Las funciones técnicas son rutas posibles de desarrollo; no constituyen asignaciones confirmadas.
- Los niveles individuales se mantienen como **NE (no evaluado)** hasta reunir evidencias de educación, formación, habilidades y experiencia.
- La escala de la matriz es 0–4; el objetivo general es alcanzar ejecución autónoma (nivel 3) en la función acordada. DevOps puede comenzar con objetivo 2, según la matriz.
- La asistencia a cursos no cierra una brecha: debe demostrarse aplicación en entregables verificables.

## 2. Rutas de crecimiento relacionadas con VeteriSoft

| Ruta | Competencias a desarrollar | Evidencia de avance |
| --- | --- | --- |
| Análisis funcional → Analista de requisitos | Relevamiento, especificación, priorización, trazabilidad y validación | SRS y RTM coherentes; requisitos verificables vinculados con pruebas |
| QA funcional → QA con automatización | Diseño de casos, pruebas unitarias e integración, automatización y reporte de defectos | Casos reproducibles, resultados de ejecución y cobertura acordada con el equipo |
| Desarrollo → Backend/API | Servicios REST, integración, seguridad y aislamiento multitenant | Endpoints revisados, pruebas aprobadas y evidencia de aislamiento entre clínicas |
| Base de datos → Datos de aplicación | Modelado relacional, SQL, normalización e integridad | DER, migraciones y consultas verificadas; pruebas de integridad y acceso |
| Gestión de proyecto → Liderazgo de entrega | Planificación, riesgos, estimaciones, comunicación y seguimiento ágil | Backlog priorizado, actas de decisión y seguimiento de hitos y desvíos |
| Operaciones → DevOps inicial | Git, CI/CD, configuración y despliegue cloud | Pipeline reproducible y despliegue documentado |

## 3. Ruta individual propuesta (plantilla)
Los datos personales se omitieron. Para completar una ruta real, registrar función acordada, objetivo profesional, competencias por desarrollar, evidencia y fecha de revisión.
## 4. Plan de mejora y apoyo

| Brecha que se confirme | Acción | Responsable de apoyo | Medición de eficacia |
| --- | --- | --- | --- |
| Requisitos o trazabilidad | Taller práctico y tutoría sobre especificación, criterios de aceptación y RTM. | Referente de análisis designado | Requisitos asignados sin ambigüedad, trazables y aceptados en revisión. |
| Diseño o ejecución de pruebas | Práctica guiada de pruebas funcionales e integración con revisión de casos. | Referente QA designado | Casos reproducibles vinculados a requisitos y resultados registrados. |
| Automatización | Programación en pareja, revisión de código y mejoras iterativas de la suite. | Desarrollador o mentor designado | Suite ejecutada correctamente en el entorno acordado y mantenible por el equipo. |
| Seguridad de datos | Tutoría sobre autorización por clínica y pruebas negativas de aislamiento. | Revisor técnico designado | Pruebas de acceso cruzado rechazadas; defectos corregidos y verificados. |
| Brecha crítica persistente | Extender tutoría; reasignar temporalmente tareas críticas o solicitar apoyo especializado. | Dirección del proyecto, sujeto a alcance y recursos | Reevaluación independiente antes de devolver la responsabilidad crítica. |

## 5. Desarrollo del resto del equipo

Para Participante A, la ruta sugerida se vincula con dirección de proyecto: planificación, gestión de riesgos, seguimiento y liderazgo ágil. Para Participante B, el acta solo registra el rol de colaborador; su ruta debe definirse después de acordar funciones y evaluar competencias. En ambos casos, el punto de partida, las brechas y las acciones se registrarán con la misma ficha de cuatro pilares, sin inferir calificaciones.

## 6. Seguimiento

1. Al inicio, acordar función, competencias requeridas, evidencia admisible, nivel objetivo y revisor.
2. Registrar nivel inicial como NE hasta completar una evaluación práctica.
3. Revisar avances al cierre de cada sprint y actualizar acciones, responsables y fechas acordadas.
4. Al completar cada acción, reevaluar con una tarea o entregable real; registrar resultado y observaciones.
5. Calcular eficacia: acciones reevaluadas que alcanzan el objetivo con evidencia conforme / total de acciones reevaluadas × 100.
6. Actualizar el plan de carrera al cierre del proyecto con logros demostrados y el siguiente objetivo profesional.
