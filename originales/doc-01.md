| **Necesidades del Cliente** | Erradicar el caos administrativo y la pérdida de ingresos que nos genera usar herramientas informales |  |  |
| **Restricciones del Proyecto** | El tiempo de desarrollo está estrictamente limitado al cronograma aprobado y al presupuesto asignado. |  |  |
| **Propósitos del Proyecto** | Desarrollar un Sistema de atención veterinario integral, cuyo objetivo medible es entregar un Producto Mínimo Viable (MVP) funcional después de los 9 meses y 15 sprints que conllevará el proyeto. |  |  |
| **Objetivos Medibles** | **Gestión** | - Completar el 100% de las historias de usuario y la documentación del MVP dentro del plazo de la línea base aprobada. |  |
| **Entregables** | - Desarrollar y poner en funcionamiento 3 módulos centrales (Gestión de Usuarios/Mascotas, Agenda de Turnos e Historial Clínico) para la fecha de lanzamiento.   - Lograr que el 100% de las consultas a la base de datos relacional vinculadas al historial de una mascota se resuelvan en menos de 2s |  |  |
| **Criterios de Éxito Asociado** | **Gestión** | - Aprobación formal de los entregables documentales (casos de uso, diagramas de clases y secuencia) por parte de la gerencia clínica mediante pruebas de aceptación de usuario (UAT), sin requerir más de un ciclo de corrección de errores. |  |
| **Criterios** | - El sistema permite ejecutar un flujo de negocio completo de principio a fin sin fallos: dar de alta un dueño, registrar a su mascota, agendar un turno y que el veterinario complete la atención médica. -  La plataforma web es completamente responsiva, permitiendo que tanto el dueño de la mascota como el veterinario puedan operar la interfaz desde un dispositivo móvil sin pérdida de funcionalidad. |  |  |
| **Requisitos de alto nivel** | Sistema de permisos segmentados por rol, recordatorios automatizados de vencimientos y un módulo de perfiles de mascotas accesibles mediante código QR |  |  |
| **Descripción** | El sistema centralizará la administración de turnos, el registro de historias clínicas de los pacientes (mascotas), el control de inventario de insumos y la emisión de alertas preventivas (como vencimiento de vacunas). El software operará bajo un modelo de perfiles con distintos niveles de acceso para dueños, veterinarios, recepcionistas y administradores. |  |  |
| **Limites** | - El sistema será exclusivamente una aplicación web responsiva; no se desarrollarán aplicaciones para plataformas móviles (por ahora).   - La integración con pasarelas de pago reales para el cobro de suscripciones o consultas quedará fuera del alcance, limitándose a un registro de pagos simulado.   - No se contempla la provisión, instalación ni configuración del hardware en las clínicas. |  |  |
| **Entregables** | - Documentación de Ingeniería   - Código Backend   - Código Frontend   - Base de datos   - Prototipo Desplegado |  |  |
| **Riesgo General** | El riesgo principal es la falta de tiempo para implementar la totalidad de los modulos planificados antes de la fecha limite de entrega, sumado a posibles complicaciones técnicas en la integración de backend con el frontend. Existe también un riesgo de desvío del alcance original al intentar abarcar funciones muy avanzadas antes de tener consolidado el MVP. |  |  |
